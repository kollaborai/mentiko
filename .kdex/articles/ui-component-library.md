# UI Component Library

## overview

shared ui component library for mentiko. built on radix-ui primitives with tailwind styling, following a flat, borderless, apple music app aesthetic. components are organized by purpose: foundations, page chrome, workflow surfaces, and specialized widgets.

all components are client-side ("use client") and use:
- `@aliimam/icons` for iconography (lucide-react is deprecated)
- `cn()` utility from `@/lib/utils` for class merging
- theme tokens: `bg-card`, `bg-muted`, `bg-accent`, `text-foreground`, etc.

## key interfaces

### registry

`UI_LIBRARY_GROUPS` and `UI_LIBRARY_RULES` in `registry.ts` define:
- which components are approved vs provisional
- where each should be used
- usage constraints (e.g., "one primary cta per panel")

## how it works

### button variants

uses `class-variance-authority` (cva) for variant management:

```typescript
const buttonVariants = cva(
  "inline-flex items-center justify-center ... base-classes",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        destructive: "bg-destructive text-primary-foreground ...",
        outline: "bg-muted hover:bg-accent ...",
        ghost: "hover:bg-accent ...",
        link: "text-primary underline-offset-4 hover:underline",
      },
      size: {
        default: "h-9 px-4 py-2",
        xs: "h-6 px-2 text-xs",
        sm: "h-8 px-3",
        lg: "h-10 px-6",
        icon: "size-9",
      },
    },
  }
)
```

### card shell pattern

most cards follow this structure:
- `Card` - outer container with `bg-card rounded-sm`
- `CardHeader` - title row with optional `CardAction` slot
- `CardTitle` - bold heading
- `CardDescription` - muted subtitle
- `CardContent` - main body content
- `CardFooter` - action buttons

### workflow card variants

`WorkflowCard` has three display modes:

```typescript
type WorkflowVariant = "compact" | "default" | "detailed"

// compact - minimal list item (title + status)
// default - standard list card (title, goal, metrics)
// detailed - full expanded view (agents list, metrics grid)
```

## patterns

### data-slot attributes

all components add `data-slot` attributes for css targeting:
```typescript
<Button data-slot="button" data-variant="default" />
<WorkflowCard data-slot="workflow-card" data-status="running" />
```

this allows:
- deterministic css selector targeting
- e2e test selectors that don't depend on classes
- visual debugging with browser devtools

### forwardref + displayname

components that wrap radix primitives follow this pattern:

```typescript
const DialogContent = React.forwardRef<
  React.ElementRef<typeof DialogPrimitive.Content>,
  React.ComponentPropsWithoutRef<typeof DialogPrimitive.Content>
>(({ className, ...props }, ref) => (
  <DialogPrimitive.Content ref={ref} className={cn(...)} {...props} />
))
DialogContent.displayName = DialogPrimitive.Content.displayName
```

this preserves ref forwarding and enables better debugging.

### loading states

`Button` supports a `loading` prop that shows a spinner:
```typescript
<Button loading={isLoading}>Submit</Button>
```

the spinner is `RotateFilled` from `@aliimam/icons` with `animate-spin`.

### status color mapping

`status-colors.ts` provides consistent status colors:

```typescript
export const getStatusColor = (status: string): string => {
  switch (status) {
    case "running": return "text-amber-400"
    case "completed": return "text-green-400"
    case "failed": return "text-red-400"
    case "pending": return "text-blue-400"
    default: return "text-muted-foreground"
  }
}
```

use this for any status indicators to stay consistent.

## gotchas

### icon migration

**never import from lucide-react**. it's deprecated. always use `@aliimam/icons`:

```typescript
// wrong
import { Check } from "lucide-react"

// correct
import { TickCircleFilled as Check } from "@aliimam/icons"
```

see `web/lib/utils/tool-icons.ts` for category icon helpers.

### composer vs chat-composer

- `ChatComposer` - simple terminal-style input, used in conversations
- `Composer` - full gaia-style input with slash commands, attachments, tools
- `SessionComposer` - wrapper that shows session status + uses `Composer` internally

use `ChatComposer` for simple agent input, `Composer` for full workspace authoring.

### web-viewport same-origin

`WebViewport` uses `/api/system/web-proxy` to load content. this:
- makes all content same-origin (bypasses cors for screenshot)
- injects a bridge script for postmessage communication
- only works for http/https urls, not custom protocols

### holo-card tilt

`HoloCard` uses `react-parallax-tilt` which can cause layout shifts if:
- parent container has `overflow: hidden`
- card size changes during tilt

use `forceSide` prop to disable tilt for static screenshots.

## dependencies

- `@radix-ui/*` - headless ui primitives
- `@aliimam/icons` - iconography (replaces lucide-react)
- `class-variance-authority` - variant management

- `d3` - graph visualization (knowledge-graph)

- `@/lib/utils` - `cn()` class merger
- `@/lib/utils/colorUtils` - color parsing for dynamic raised-button
- `@/lib/utils/tool-icons` - category icon helpers
- `@/lib/status-colors` - consistent status colors

css:
- `wave-spinner.css` - spinner keyframes
- `holo-card.css` - holo-card animations
- `markdown.module.css` - markdown styling
